# 提示词文风审校

先读 [提示词写作与古风清理](../../../docs/archaic-wording-cleanup.md) 的语体、写作规则和保留项，审校任务指定的文本或本次改动。语体规则适用于所有提示词；古风清理只针对文言和修仙话术。

## 定位模型输入

通过源码检索确认提示词正文及其对应的配置和测试约束：

| 来源 | 要核对的入口 |
| --- | --- |
| 世界书正文与注入规则 | `任务助手-世界书.ejs` |
| 共享配置与前端注入逻辑 | `src/data.js` 及 `src/` 下相关模块（注意与 `任务助手-世界书.ejs` 的 `@data` 同步） |
| 提示词回归与规则测试 | `test.mjs`（修改提示词结构或规则文案时同步核对测试断言） |
| 文档与更新记录 | `README.md`、`使用说明.md`、`CHANGELOG.md` |

## 审校

先按语体检查口语、网络用语、语气词和作者口吻，规则正文里的玩家统一写 `<user>`；角色台词与示例对白保留角色口吻。

读完整段落，结合西幻设定与任务助手机制判断词句整体风格；检索用于补漏（如 `于/其/皆/亦/乃/均可`、修仙词、口语词）。

检查冗余时，对照会同时注入的规则和模板，找出重复提醒及缺少具体依据的防错要求。条件分支（如 `null核心`、未接取/已接取、限时/常驻词条）按各自实际激活的上下文判断。

改写自然语言，保留设定含义、EJS 模板逻辑和 MVU 变量写入约定。审查任务给出文件位置、原句、原因和建议；修改任务完成后简要说明改动，并运行 `node --test test.mjs` 验证（若改动 `src/` 还需运行 `node build.mjs`）。
