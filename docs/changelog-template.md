# 更新日志模版

本模版用于规范 [CHANGELOG.md](../CHANGELOG.md) 的记录格式。所有更新按**重要程度从高到低**划分为四类：**重要更新 → 优化 → 修复 → 其他**；当次更新中无对应内容的分类可省略，不留空标题。

## 标准模版（直接复制使用）

```markdown
## YYYY-MM-DD

### 重要更新
- **【模块/功能名】简明标题（`commit`）**：说明新增的核心能力、机制调整或架构变化，以及对玩家或配置的影响。

### 优化
- **【模块/体验】简明标题（`commit`）**：说明交互细节、视觉表现、提示词精简、性能或 Token 占用方面的改进。

### 修复
- **【问题定位】简明标题（`commit`）**：说明修复的具体故障现象、根因或边界兜底场景。

### 其他
- **【文档/工程】简明标题（`commit`）**：说明文档补充、协作规则、测试脚本、构建配置或资源文件变动。
```

## 填写约定

1. **分类顺序固定**：严格按 `重要更新` → `优化` → `修复` → `其他` 排列，便于快速定位核心改动。
2. **重要程度划分**：
   - **重要更新**：新功能上线、核心规则/数值机制调整、数据结构或变量路径变动。
   - **优化**：已有功能的体验打磨、UI/文案改进、去古风与提示词标准化、耗时或上下文开销缩减。
   - **修复**：逻辑 Bug、状态残留、竞态写覆盖、解析异常或兼容性问题修复。
   - **其他**：README/使用说明/规范文档更新、测试用例补充、构建工具或非代码资产调整。
3. **影响标记（按需附加）**：
   - 涉及前端脚本重新打包或世界书正文变更时，可在版本标题下或条目末尾注明 `【需更新脚本】` / `【需更新世界书】`。
   - 若存在破坏旧存档或需手动迁移的改动，标注 `【不兼容】` 并附处理说明。
4. **书写风格**：保持客观、简洁的书面语，写清「改了什么」与「带来什么效果」，避免空泛描述；同一阶段连续多个小提交可合并成范围写法（如 `` (`78eaa88` ~ `6c43f64`) ``）。
